# ATOM capability evidence matrix

Read the [scope, tool inventory and source index](SOURCES.md) first. This matrix
describes main at the revision recorded in the README, refreshed on 2026-11-11;
it does not describe a measured benchmark run. Capability IDs are stable references for later authoring.
The [Ethos draft](ETHOS.md) captures the intended behavior that can be derived
from these sources; unresolved product intent remains explicit.

## Evidence and failure labels

- **P:** explicit prompt/role expectation. Instructions alone do not enforce it.
- **D:** documented contract or limitation.
- **I:** implementation supports or enforces the specified mechanism.
- **T:** relevant test source/assertions inspected; **not run in this pass**.
  Tests may use fake/scripted models or a related framework/derived agent; see
  [test-fixture scope](SOURCES.md#test-fixture-scope).
- **Proposed evaluation check:** an authoring suggestion, not an existing task
  or evidence of model success. These columns deliberately identify what source
  inspection cannot establish.

“Tested failure path” means regression coverage exists in source; it does not mean
an open defect or a measured failure rate. “Documented limit” is an intentional or
acknowledged boundary. Prompt-only behavioral risks are identified as unmeasured.
The list is scoped to evidence inspected here, not a complete issue-tracker audit.

## Gaps that matter for Eval Author

The largest gap is between a scripted test exercising an API and a real model
choosing that API appropriately. In particular, C09/C25 (verification of delegated
work), C14 (object/reference use), C16 (library/environment choice), C17 (recovery
after feedback) and C18–C19 (using partial/archived evidence) need behavioral tasks.
Their runtime plumbing is not equivalent to measured task coverage.

Default single-session behavior, orchestration, host lifecycle, conditional
extensions/media, and experimental reflection should be separately tagged.
Unsupported deployment features should not become automatic agent failures.
Changing those scopes requires a later decision; this pass does not choose them.

Existing framework capability cases are starting evidence ([S22](SOURCES.md#s22)),
not proof that ATOM or Paul's current benchmark exercises these rows. Historical
unified-work results ([S23](SOURCES.md#s23)) belong to their original commits.

Every generated case should eventually identify its capability ID, required
environment, observable success check, relevant failure control, and evidence
needed to show the capability was exercised. These are preparation criteria,
not a generated suite or a configured mutation study.
